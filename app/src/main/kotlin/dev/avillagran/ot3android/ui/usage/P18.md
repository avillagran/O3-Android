Reference: Desktop feat/o3-brand, audit rows 097–099, 129, 273, 398 and P18.

## Shared-library boundary

Pinned lib v0.3.5, source d4bf6054b4480efdcd8a436cb66cb7f2e23664b1,
exports quotaSources.apply/limits/providers/sources, not quotaSources.present.
Confirmed against that commit's src/domain/usage.rs, not an assumption about lib HEAD.
The Limits page explicitly describes the individual reports. Kotlin never joins by
email, workspace or fingerprint, selects a winning observation, sums shared quotas,
calculates pool pace, or guesses ambiguous identities. U26 exact pools, earliest
pool reset, relative reset/pace, identity ambiguity and reset-credit redemption remain
unavailable. Reported per-window reset timestamps remain device-local, with strict
RFC3339 parsing; malformed timestamps are omitted. Sanitized auth only distinguishes
authenticated/unauthenticated; no specific access-denied reason is invented.

The existing usageSummary projection owns day/week/month/quarter, device timezone,
cost/tokens/session/cache-savings totals, daily bars, model breakdown and pricing
status. Android keeps its cost/token toggle and touchable daily values. The refresh
button on Limits now probes the existing shared subscription, preserving per-host
five-minute probe pacing; failures remain visible alongside existing data. Disconnect
clears the old host data. Last consumer release cancels the reducer and retries.

## Android adaptation

Four local delivery modes: notifications, notifications with sound, sound only, off.
Existing installations preserve sound-enabled alerts. Native awareness still consumes
all transitions, even with delivery off, so enabling a mode does not replay old events.
The background-follow opt-in remains independent: Android requires its silent service
notice even in sound-only/off mode. The foreground card/leases and idle-stop policy
remain the existing mobile lifecycle adaptation, not a Desktop window/bar replica.

Banners and summaries are silent; adjacent native batches coalesce for 200 ms and play
one system channel sound, not one per child. While playing (maximum three seconds),
additional batches share that sound. Android uses the user's alert-channel sound for
both input and completion; Desktop's two bundled chimes are not shipped. Channel
importance, disabled sound, notification permission and app-level blocking are honored.
Disabling sound or destroying the service cancels pending/playback work. Alert-channel
blocking is shown with an Android settings action; activity-channel blocking prevents
starting the background service. Settings recheck channel state on resume.

## Acceptance limits

Unit/Robolectric tests verify lifecycle argument/baseline ownership, persistence,
coalescing/cancellation, blocked channels, quota refresh sharing/failures, reconnect and
strict reset date fixtures. Native awareness dedupe tests require host libt3_jni.so;
a skipped native test is not evidence of live JNI behavior. Real host auth, background
reconnect under Doze/OEM restrictions, device sound/DND, notification permission UI,
RTL/accessibility and exact U26 pools await native/device acceptance. No phone touched.
